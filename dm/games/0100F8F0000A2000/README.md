# Splatoon 2, European release (`0100F8F0000A2000`)

I registered an **experimental** profile for update **5.5.2** (`v3342336`), SDK **3.4.1**, NVN **53.313**, Nintendo's sead / agl / gsys engine. I tested this exact European build on an Apple M5 Max with macOS 27.2 on November 1, 2026. This profile does not qualify other regional executables, iOS gameplay or complete online/local matches.

## Verified milestone

I reached the real character creator, completed its selections, and entered the rendered 3D introduction with Spanish text and audio initialization. I then completed the tutorial with a physical controller and reached the rendered 3D plaza. I have not played a LAN, local-wireless or Nextendo match in this build. DLC discovery is not DLC gameplay validation.

I kept the original rewritten game code, with no per-game function cuts. The shared native host supplies the SDK services. Its passive Nextendo account check runs in a bounded process of the same executable on macOS, so legacy Keychain interaction cannot hold the rendering process at startup; explicit account access remains separate. See [passive account preflight](../../../docs/reference/services.md#game-startup-waits-in-keychain-before-its-first-shader-draw).

## Shaders and first startup

I scanned RomFS and `main` and split the recognized inputs: **74,541** unique shaders (29,664 vertex, 44,843 pixel, 19 compute and 15 geometry), with 51,462 BNSH pairs and 7,944 supplemental pairs. The tables contain hashes, binding facts, container locations and pairing metadata; no shader binaries or translated libraries are included. This is not a claim of complete runtime shader coverage.

I initially recorded **three splitter warnings**: `System/GSys/gsys_resource_nvn.szs`, `gsys_resource_nvn_dev.szs` and `gsys_resource_nvn_win.szs`. The first two are valid big-endian SARC archives that the old reader misread. I then positively identified the common BAHS v9 payload in all three as **307 GX2 shader records** (153 vertex, 153 pixel, one geometry), validating their public structure layouts, modes, aligned code ranges and complete program coverage. The general reader now handles SARC byte order and classifies this bounded foreign format; unknown or damaged BAHS still fails. This decision does not depend on filenames or the absence of an NVN marker. See [shader-container validation](../../../docs/reference/shaders.md#containers-by-engine).

I reran the complete **registered-profile** split, including all five DLC images, with provisional and damaged-input modes disabled. It completed in 123 seconds with **zero unreadable files** and the same 74,541 shaders. The production guard accepted all four shader tables, the registered inputs remained unchanged, and every one of the 15 generated package files (765,063,008 bytes) matched the qualified reference by SHA-256. No translation, library or stamp was replaced. The actual `gsys_resource.Nin_NX_NVN.debug.szs` and `.release.szs` contribute 72 and 70 unique keys already in the map. This verifies the registered extraction path; complete runtime shader coverage and gameplay remain open.

My tested library used translation chain `a7dbbce711c3` and profile-input digest `6b44c021109c`. The generated tables and `shader_note` keep their original labels, including the word “provisional”, to preserve that byte-verified input identity. This label does not replace the qualification above. Generated `c1_full.tsv` and `cb_extent.tsv` must come from the actual shader build and its matching stamp.

My first offline-startup log recorded a 241.9-second pipeline prebuild: 59,406 pairs, 59,399 base pipelines built, seven deferred, zero failures. I observed the 3D character creator after that stage. I have not qualified the initial progress interface during that interval or an iOS shader build.

I later reproduced first-scene pauses of 8.85, 7.21 and 5.35 seconds associated with runtime shader/library and render-pipeline compilation. The installed bundle's prewarm manifest contained no states. I collected 4,655 distinct states from my actual tutorial/plaza runs, checked their library/reflection presence and render-state parsing against the same chain and profile inputs, and included that private manifest in my installed Mac candidate. I also corrected the shared prewarm reader's rejection of valid geometry-library suffixes; unknown suffixes and absent base keys still fail.

With that candidate, I observed 3,900 focused plaza frames at 30 fps, the game's requested swap interval of two, and zero discarded frames. The largest observed long frame was 113.8 ms with no compilation; GPU medians were 4.83–7.80 ms. Preparing 2,501 libraries, 2,151 render pipelines and three compute pipelines took about 5.5 seconds on the first measured start. The next start reused the archive and prepared the expanded 2,503/2,153/3 set in 168.9 ms. I did not repeat an identical controller route, and I have not qualified unseen stages, battle performance or iOS. New states can still require compilation and are recorded for a later start. See [recorded geometry libraries and prewarm](../../../docs/reference/shaders.md#recorded-geometry-libraries-skipped-by-the-prewarm).

### Open runtime shader findings

My tutorial/plaza run reported 16 shader keys absent from the registered map. No control/code captures from those keys are available yet, so I have not attributed the mismatch to a missing container, runtime specialization or key lifetime. The successful strict split above does not resolve these runtime failures.

On November 2, I inspected a scene with reddish/orange character skin under the green umbrella. I have not yet established whether this is a material/shader or presentation defect, or reproduced a matched original-console reference. All 16 missing keys already appeared in earlier pre-background logs, and the installed map/pair tables match the registered profile. This does not clear the material: character colors remain unqualified, and I have not applied a skin-tone, gamma or sRGB workaround.

The same run reported two geometry-reader/fragment interface mismatches. Both original geometry programs declare a maximum of one output vertex but immediately exit without an `OUT` instruction; their translated kernels emit no vertices. Their readers expose position and point size only, while the fragment stages require generic attributes. I corrected the shared host's handling of positively identified zero-emission geometry: the compute/stream-output work remains, while an impossible raster draw is omitted only when complete reflection establishes that no raster output exists. Synthetic GPU tests cover the correction, and my installed candidate reached the plaza without those pipeline failures. This does not resolve the 16 absent shader keys above.

## Network requirements and remaining tests

I included automatic service preparation and validated a real refresh of the public Nextendo BCAT schedule during startup. I now check for calendar changes on every online launch before SDK initialization or the first game calendar open, with a shared 12-second network budget and the last validated copy retained on failure. I verified two consecutive launches of the installed Mac port: both queried the live provider and selected the unchanged validated calendar before `nnMain`. Synthetic changed-calendar tests separately check that the first open reads the new snapshot. [BCAT preparation and runtime delivery](../../../docs/reference/nextendo-bcat.md) describes its HTTPS, signed eligibility and local-cache checks. Downloading schedules and finding service profiles do not prove online play. The provider's [signed game catalog](https://nextendo.network/service-catalog/v1/game-catalog) and [compatibility guide](https://wiki.nextendo.network/games) describe its service requirements independently.

For local play, Nintendo documents both [local wireless](https://en-americas-support.nintendo.com/app/answers/detail/a_id/27031/) and [the Shoal's LAN mode](https://en-americas-support.nintendo.com/app/answers/detail/a_id/27035/), enabled by holding **L + R + Left Stick** for several seconds in the Shoal. I have not yet reached or tested either path with this native profile. Symbol coverage is narrower evidence: all 25 LDN, 32 socket and eight NIFM imports have a native hook or their original exported SDK helper; it does not validate protocol behavior or a match.

My first online attempt returned to the plaza. The bounded account/NIFM trace recorded a valid local account handle and an available network, but no available network-service account. The real same-executable helper sent a valid reply with availability false; I observed `SecItemCopyMatching` returning `errSecAuthFailed` before credential decoding while the default Keychain was unlocked. I added an explicit per-port account authorization action, preserving passive startup and the complete credential checks. After authorizing access through macOS, I verified a real account Result of zero with availability true; the same result persisted from the first check after a fresh launch. My installed candidate uses my existing Apple Development signing identity, with a certificate-based designated requirement. This establishes local credential access, not a working NEX session or online match. Further online qualification remains open.

I then traced the schedule/news prerequisite to the original `Cmn::NetworkTime` task consumer. The old host always failed `AsyncEnsureNetworkClockAvailabilityTask::GetResult`, preventing its ready state. A title-only HLE count captured constructor, initialization, start, finish-event lookup and result retrieval once each, confirming this path executes in the real game before any lobby test. I implemented the [checked kernel network clock](../../../docs/reference/services.md#synchronized-network-clock-and-availability-tasks) and installed the candidate with the same signing requirement. In the physical retest, I passed the previous schedule warning and reached the internet-connection screen, then returned to the plaza. Five account-token/cache and DNS attempts were counted, with no socket creation or TLS handshake; I have not reached an online lobby or match.

I separately decoded all four schedule BYAML files and verified the same nine file hashes in the bundled seed and two runtime snapshots. The containers are BYAML v2, with an internal `Version` field of 26; those numbers do not denote the game's 5.5.2 version. On November 1 in Tijuana, VS and Coop both contained a currently active UTC rotation. Festival's explicit 2020 event does not expire those separate rotations. The native VS/Coop parser computes Gregorian POSIX seconds directly, and the selector compares them with raw network-clock seconds; I found no host-time-zone conversion in that path. Container validity, current date coverage, schema acceptance and successful game selection remain separate checks.

On November 2, I isolated the next `2306-0502` failure with bounded numeric TLS results. The first connection verified the explicitly approved service certificate, completed TLS and exchanged application bytes. A second connected socket supplied an IPv4 literal as its TLS name; the DNS-only admission policy rejected that name before its handshake. The existing [paired numeric handoff](../../../docs/reference/services.md#nex-secure-server-handoff-loses-the-enrolled-tls-service-identity) retains the approved logical service, SNI and exact certificate for that address. With this pair, both real connections verified and completed TLS, and I entered the online lobby and the Territorial matchmaking queue. I have not completed a match or qualified peer-to-peer gameplay. Studio's Mac packer now prepares the paired profile from the private, title-scoped approved-certificate collection and current public routes; it does not require editing an IP for each export or enroll new certificates automatically.

## Found on this game

- [CPU-written textures](../../../docs/reference/nvn-objects.md#cpu-written-textures): I traced the tutorial's R32F 256×4, stride-1024 linear render target to `WriteTexels` incorrectly taking block-linear addressing and upload classification. Synthetic byte and GPU readback tests cover the general correction separately from game qualification.
- [Same-pass feedback](../../../docs/reference/rendering.md#same-pass-feedback-read-through-a-snapshot): I observed `0be625d3c994c796_b`, slot 2, sampling a single-level 2D attachment through a shader-declared 2D array. The generic snapshot path must preserve its one-slice type adaptation and the existing mip, layer and multisample guards.
- [Geometry-library prewarm](../../../docs/reference/shaders.md#recorded-geometry-libraries-skipped-by-the-prewarm): I found 22 valid observed geometry-library/reader rows rejected as stale by suffix validation.
- [Passive account preflight](../../../docs/reference/services.md#game-startup-waits-in-keychain-before-its-first-shader-draw): I separated successful helper transport from a real Keychain authorization failure before credential decoding.
- [Cancellable socket DNS](../../../docs/reference/services.md#cancellable-socket-dns-still-enters-the-console-resolver): I traced the unimplemented two-argument resolver used by CURL to the console-only state left unavailable by the host initializer. I added real native resolution and cancellation. In the installed Mac retest, I counted two calls to the new resolver and two real Socket/Connect sequences, followed by TLS setup and 18 handshake calls. The game still requested `2306-0502` and did not reach a lobby or match; online qualification remains open.
- [Network clock](../../../docs/reference/services.md#synchronized-network-clock-and-availability-tasks): I confirmed the old fixed task failure executes before the title and prevents the schedule prerequisite from becoming ready.
