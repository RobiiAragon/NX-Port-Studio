# NX Port Studio 1.6.0 — Release Candidate 7

I prepared **RC7** (`v1.6.0-rc.7`, Studio **1.6.0 build 24**) to correct reproducible problems found while qualifying freshly rebuilt game ports. I keep the candidate experimental; a successful export, service connection or lobby entry does not establish a completed online match.

## Changes

- I prepare graphics-tracked guest memory immediately before each native socket receive, including attempts after a readiness wait or a partial stream read. I also prepare the validated output span before `GetSockOpt` calls the kernel. A kernel copyout cannot invoke the runtime's user-space dirty-page fault handler: a valid tracked destination could previously fail with `EFAULT`. I reproduced that failure with the real dirty-page tracker and actual loopback TCP/UDP. I preserve errors for invalid and unregistered read-only destinations. This change does not add blind receive retries or make preparation atomic against concurrent re-protection.
- I recorded Smash 13.0.5's observed `near=0` depth mode in its profile. My complete RC6 export had bundled `near=-w` pipeline bases, which the runtime correctly rejected; it then rebuilt 31,148 bases in 217 seconds on this Mac. New offline archives use the observed mode. Runtime depth handling, archive validation and shader chain `a7dbbce711c3` remain unchanged. I regenerated all 31,148 bases without failures; my installed Mac app accepted the corrected archive and found all 16 sampled bases in 3.7 ms. It did not repeat the previous full preparation.
- I removed online account authorization from local presence initialization. The initializer now validates the SDK layout and an existing local UID, then copies that UID without credential reads or HTTP requests. My synthetic social fixture passed 174 checks in normal and ASan/UBSan runs, including offline modes, absent accounts, invalid UIDs and untouched object fields. Publishing presence remains authenticated and can still fail; this change does not make every subsequent account or social operation noninteractive.

I include the existing background execution, fullscreen presentation policy, LAN/LDN, signed iOS export and Nextendo integration from [RC6](1.6.0-rc.6.md). Updating Studio does not replace game apps already installed: I must rebuild and reinstall each port to include runtime changes.
