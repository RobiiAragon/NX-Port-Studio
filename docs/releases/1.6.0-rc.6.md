# NX Port Studio 1.6.0 — Release Candidate 6

I prepared **RC6** (`v1.6.0-rc.6`) with the combined source changes below. I keep this release experimental: a successful build or service connection is not complete game, rendering or online qualification.

I set the package metadata to **1.6.0, build 23**, labeled **Release Candidate 6**. This identifies the intended Studio package; I still need to verify the final packaged artifact and its embedded engine before publication.

## Changes I prepared

- I registered the experimental **Splatoon 2 EUR 5.5.2** profile and its reproducible shader metadata. I corrected CPU-written linear textures, one-slice framebuffer feedback, SARC byte order and bounded foreign BAHS recognition. I preserve the established shader chain `a7dbbce711c3`; the repository contains hashes, pairing facts and source locations, not original or translated shader binaries. I also corrected positively identified zero-emission geometry handling without removing passthrough vertex/fragment pairs.
- I refresh Splatoon 2 calendars before SDK initialization on an online launch, retaining the last validated snapshot if refresh fails. I keep public HTTPS authentication, signed catalog eligibility, archive/content checks and read-only delivery separate. A valid calendar alone does not establish online play.
- I added an explicit per-port Mac account authorization action while preserving bounded passive startup. I implemented network-clock availability from the kernel's actual synchronization and precision state. I also added cancellable native DNS resolution with genuine completion and guest-wait handling.
- I added bounded numeric account, Poll and TLS diagnostics that preserve errno and exclude account values, names and stream contents. I prepare Mac numeric TLS handoffs from the private, title-scoped collection of certificates I explicitly approved, preserving the logical service identity and its exact certificate. When an approved host already has an exact public rule, I promote only its private copy to the exact approved pin at the same destination; the public source and unrelated routes remain unchanged. This does not enroll new certificates or weaken unresolved trust failures.

I added default continued execution in the background, independent input/visibility state, safe presentation handoff and standard Mac Hide/Minimize commands. I retain the existing primary-process Mac launcher, signed iOS export path, private Mii import foundation and LAN/LDN backend. I preserve nxnative's authorship and license notices. Updating Studio does not automatically replace previously exported game apps.

I also synchronized the [Mac fullscreen presentation policy](../reference/frame-rate.md#frame-latency-2-for-the-display-link-in-fullscreen): the extra display-link frame is requested only for variable-refresh fullscreen, with automatic updates when the screen or its mode changes. Fixed-rate displays keep the normal latency. My production-policy and AppKit classifier fixtures pass; physical fullscreen gameplay remains a separate check. I exclude locally generated shader-library ABI tables from the portable Studio source snapshot, and the package checker now rejects them. Each private game build regenerates those tables with its own shader libraries and chain stamp.
