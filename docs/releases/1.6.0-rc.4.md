# NX Port Studio 1.6.0 — Release Candidate 4

RC4 packages the native-networking corrections integrated after [RC3](1.6.0-rc.3.md). The release tag is `v1.6.0-rc.4`; the Mac bundle is version `1.6.0`, build **21**. This remains a pre-release, with per-game hardware qualification of the synchronized engine still open.

## Changes

- Select an eligible Wi-Fi or Ethernet adapter for local discovery when the default Internet route belongs to a VPN. Explicit interface overrides remain authoritative. Automatic/Nextendo IP reporting keeps its existing route semantics, and a VPN gateway is never attached to a different LAN. This does not establish every game's behavior with a VPN.
- Retire exhausted discovery sweeps before coalescing a new query. A completed one-peer sweep can no longer absorb the next identical datagram. An explicit repeated-query regression is separate from the directed-broadcast nonce test; pending sweeps retain their coalescing and traffic bounds.
- Handle the LDN wireless-controller policy through the native context and its wait/lifetime path. Smash 13.0.5 no longer needs to fall back to an SDK service object that native initialization did not create. The Apple IP bridge retains the valid policy request without claiming to reproduce the console's shared Bluetooth/LDN radio budget.
- Recognize nested and continued socket-hook wrappers in import surveys, while preserving the distinction between weak hooks and forced takeovers. This corrects reported hook coverage; it does not add a new online service implementation.
- Document all 16 intersections between revision 19 of the signed Nextendo catalog and native profiles. Fourteen profiles declare a catalog-accepted build; Scarlet and Violet still need native qualification of the required 4.0.0 update. A matching profile or version does not establish a playable native online match.

RC3's restoration of passthrough geometry and tessellation shader pairs remains included. RC4 does not change the shader translation chain: the reference stays Xcode 27.2 / Metal 32023.922, chain `a7dbbce711c3`. The engine baseline remains nxnative `d2a86b05ccce`, with the original authors and notices preserved.

## Validation and limits

The integrated changes in [Studio #3](https://github.com/RobiiAragon/NX-Port-Studio/pull/3) passed all 12 emitted checks. The updated [Studio #2](https://github.com/RobiiAragon/NX-Port-Studio/pull/2) passed all 11 emitted checks, including the protected branch's four required checks, static analysis, host/graphics tests, sanitizers, and Mac/iOS compilation. The synthetic iOS app also compiles and links without signing or installation.

Local production-host validation found 995 unique forced takeovers, and all 202 iOS host sources compiled. The composed network fixtures passed 4,694 discovery checks, 836,727 protocol-classifier checks, 14 interface-selection checks, 94 socket checks and 14,854 LDN checks normally and under ASan/UBSan, plus the LDN lifecycle/event fixtures. Removing the repeated-query fix makes the explicit second-packet regression fail; restoring it makes the fixture pass. These are synthetic and loopback mechanism checks.

No new physical game session is claimed for RC4. The earlier Mario Kart 8 Deluxe 3.0.5 LAN/LDN results across native Mac/iOS ports and a modified physical Switch, and the Mac Smash 13.0.5 Nextendo arena round, remain separate baselines. Built-in LAN can work with stock consoles when a game supports LAN; the IP LDN bridge requires a compatible console module. This release does not certify all games or host/device pairings.

Nextendo remains experimental. Quickplay stability and broad native online compatibility remain open. Mario Kart 3.0.5 remains below the catalog's required 4.0.1. Account authorization, service routes and accepted versions are separate from a completed online match; see the [coverage inventory](../nextendo-coverage.md).

The Mac Studio package uses a local ad-hoc signature and is not Developer ID notarized. It includes no game, firmware, console key, account credential or signing identity. Game IPAs still require the creator's Xcode team/device signing. Source and package artifact checks remain part of release preparation.
