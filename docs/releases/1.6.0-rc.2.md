# NX Port Studio 1.6.0 — Release Candidate 2

This candidate integrates the current nxnative engine while preserving Studio’s signed iOS export, native controls, imported system resources, automatic local networking and experimental Nextendo services. It is a pre-release: the newly synchronized engine has not yet repeated the game-by-game hardware qualification of the earlier installed ports.

## Changes

- Synchronize the engine with nxnative `d2a86b05ccce`, incorporating 352 commits after the shared `4639c5114cbb` baseline. Preserve upstream attribution and the checked shader translator.
- Bring in upstream Metal/NVN correctness, shader translation, movie/audio, memory/SDK support, portable RomFS images, cloud-save synchronization, cheat support, settings metadata and additional game profiles.
- Reconcile blocking native calls with the new per-thread gate stack. Preserve real guest registers through pause/resume without placing a large native frame on the guest stack.
- Preserve automatic LAN/LDN discovery, host and join paths, safe descriptor lifetimes, local play-history identity and scoped online policies.
- Mac exports install directly in Applications and remove their owned compilation workspace after completion or cancellation. Existing game sources, saves and private resources are retained.
- Preserve Spanish as Studio’s default and all five interface languages. README captures remain original Studio UI and match their documentation language.
- Avoid creating direct vertex/fragment shader pairs for BAHS programs containing geometry, tessellation or unknown intermediate stages. Keep all shader stages available for their actual translation paths.

## Corrections after RC1

- Include the latest upstream fix preserving shader image writes when color attachments are stored.
- Restore the iOS Joy-Con stick helper after the input-model merge and clear physical-controller state through the active controller model when the app goes into the background.
- Prepare mobile shared codecs and the platform-specific static crypto library in the full iOS compile/link fixture.
- Handle invalid sensor-player handles, incomplete haptic pairs and nullable native TLS/API inputs explicitly.
- Exercise real per-thread gate stacks in account and TLS fixtures. Their synthetic account checks and 297 real loopback TLS checks pass both normally and under ASan/UBSan.
- Pin the lint environment’s NumPy dependency and retain the static-analysis baseline without adding findings.

## Validation and limits

The macOS host compiles and validates 994 unique HLE registrations. The host suite, 852 Python tool tests (16 optional skips), 50 iOS workflow tests, Studio tests, synthetic Metal graphics fixtures and LAN/LDN ASan/UBSan checks pass. The full production iOS project compiles and links with synthetic modules, without signing or installing the fixture. Shared macOS and full iOS launcher Swift sources also pass type checking.

The owner confirmed working Mario Kart 8 Deluxe 3.0.5 LAN and LDN sessions across native macOS/iOS ports and a physical Switch before this engine synchronization. These results are retained as that baseline, rather than attributed to the new shader chain. Built-in LAN can interoperate with stock consoles that support it; IP LDN requires a compatible console module. The tested physical console was modified.

The engine’s reference compiler is **Xcode 27.2 / Metal 32023.922**, matching this development Mac. The reference shader chain is `a7dbbce711c3`. The explicit CLI `--allow-other-metal` remains available for deliberate experiments with other compilers and is never enabled silently.

Nextendo remains experimental. Smash arena participation does not establish Quickplay stability; Mario Kart 3.0.5 remains below the service’s required 4.0.1. This release contains no game, firmware, console key, account credential or signing identity. The Mac app has a local ad-hoc signature; Developer ID notarization is not claimed. Game IPAs still require the creator’s Xcode team/device signing.
