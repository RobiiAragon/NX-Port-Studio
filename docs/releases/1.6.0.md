# NX Port Studio 1.6.0

1.6.0 gathers the eleven release candidates I published since 1.4.2 into one release. It brings the current nxnative engine, online, LAN and local wireless play from each game's own menus, Splatoon 2 and Splatoon 3 12.0.0, JKSV save transfer, and wired third-party controllers on the Mac. The [games table](https://github.com/RobiiAragon/NX-Port-Studio/blob/v1.6.0/README.md#games-with-online-and-local-play) says exactly what I have tested for each game.

## Engine and graphics

- I synchronized the engine with upstream nxnative (352 commits after our shared baseline) and keep its authorship and MIT notice. Upstream's Metal/NVN, shader, movie, audio, memory and SDK work, portable RomFS images, cloud saves, cheats and new game profiles came with it.
- **Stale floating-point storage.** A render target placed over memory that held other data starts as that data; the Switch's blender discards NaN where Apple's keeps it. In Splatoon 3's lobby, 35 % of the environment-probe texels stayed NaN and every reflecting material spread them. Those texels now start from 0, only in memory the CPU cannot write, so content a game uploads on purpose stays as it is. A zero-weight blend guard from upstream (seedds, `0662f9d8`) also turns a NaN colour into 0 where its blend weight is zero; that moved the shader chain to `e00d4dfc770d`.
- Splatoon 2 EUR 5.5.2 and Splatoon 3 12.0.0 are registered, with their shader metadata (hashes and pairing facts, never shader binaries). Smash's offline pipeline metadata is corrected, and passthrough geometry keeps its shader pairs.

## Mac ports

- A Mac game renders in the app's own process, sharing one lifecycle with its settings window. It keeps running in the background, supports Hide and Minimize, and requests the extra display-link frame only in variable-refresh fullscreen.
- **Wired Switch pads.** My PowerA "NSW wired controller" is a plain USB HID gamepad that macOS's GameController framework does not list. The host now reads the 20 wired Switch pads in SDL's list (PowerA, HORI, PDP, ZUIKI) straight from HID: each becomes its own player and follows Combine and the Controls… bindings. `DM_PAD_HID=0` turns this off.
- A packed game can link or renew its Nextendo account itself: open its settings window and choose **Sign in with Nextendo** under **Online play**.

## Online, LAN and local wireless

- **Nextendo.** I fixed three things in Splatoon 3 12.0.0's signed adapter: its code in the text segment's page padding, its embedded root certificate, which the rewriter had taken for code, and the provider's public host name. TLS handoffs use only the certificates I explicitly approved. DNS resolution can be cancelled, and the network clock follows the kernel's real synchronization state.
- **Presence.** Splatoon 3 never publishes presence, so friends on Nextendo's emulator could not see me. In Nextendo mode the host now publishes the game every 45 s, and sign-in requests the `presence` permission. An account linked before 1.6.0 must sign in again (**Sign in again…**) to grant it.
- **Pia's UDP socket.** Pia closes its NAT-check socket and binds a new one on the same port. In Nextendo mode the host keeps the closed socket for 5 seconds and hands it back, so a router keeps the same public port. `DM_NET_UDP_KEEP=0` turns this off.
- **LAN and LDN.** Local discovery picks a Wi-Fi or Ethernet adapter when a VPN owns the default route. A finished discovery sweep no longer swallows the next query, and Smash's LDN wireless-controller policy works through the native context.
- **Splatoon 2 calendars** arrive through BCAT before SDK start-up. They are checked for bounds, paths, CRCs and structure, and the last valid copy is kept for offline play.

## Saves and Studio

- **JKSV save transfer** in Studio and in Mac and iPhone ports: import a backup, export a flat JKSV ZIP, browse its files, and keep the previous save as a recovery copy ([guide](https://github.com/RobiiAragon/NX-Port-Studio/blob/v1.6.0/docs/save-data.md)).
- **Firmware → Import Miis** keeps a private library of your own Miis, separate from the firmware's models. A new port uses the most recently imported firmware when none was chosen. Studio keeps its five languages, with Spanish as the default.

## What I checked

- The CI of every candidate: source checks, host and graphics tests, ASan, UBSan and TSan, Mac and iOS compilation, Studio's Swift tests and the tool tests. For 1.6.0, the Mac host validates 1,048 HLE takeovers, and the documentation tests pass.
- From this code I rebuilt my Mac ports of Link's Awakening, Super Mario Odyssey, Splatoon 2, Mario Kart 8 Deluxe, Smash and Splatoon 3; each passed the host's startup check.
- The packaged app and its extracted ZIP pass the signature and content check, which finds no local build path and confirms an embedded engine.

## Limits

- I have not finished a Splatoon 3 Turf War match, Smash Quickplay or a Splatoon 2 match, and I have not yet seen a presence publication succeed.
- LAN and LDN are qualified only for Mario Kart 8 Deluxe 3.0.5, and online play on iPhone is not qualified.
- 120 fps in Splatoon 3 is not possible without generated frames: its gameplay advances a fixed tick per frame, so halving its frame step still ran at double speed.
- Studio has a local ad-hoc signature and is not notarized. iPhone exports use the creator's own Xcode signing.
- **Rebuild a port to get these changes;** updating Studio does not update an exported game.

I include source, original UI and third-party notices only. Game data, firmware, keys, personal saves and account credentials remain private.
