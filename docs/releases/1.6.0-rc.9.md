# NX Port Studio 1.6.0 RC9

I corrected the graphics defect that blew out Splatoon 3's lobby in black and white. I also registered Splatoon 3 **12.0.0** and made its Nextendo online variant connect. On my Mac, 12.0.0's plaza, lobby and practice area now render as they do on my Switch, and the game enters the online lobby and matchmaking queue.

## Graphics

- **Stale floating-point storage starts from zeros.** A render target placed over memory that held other data starts as that data. The Switch's blender then discards it even where it decodes as NaN ("zero times anything is zero"); Apple's computes NaN × 0 = NaN and keeps it. In Splatoon 3's lobby, 35 % of the environment-probe texels stayed NaN, and every reflecting material spread them. A new floating-point texture whose storage is more than 1 % NaN or infinity now starts from zeros, as a fresh one does. This applies to every game. [Reference entry](../reference/nvn-objects.md#stale-floating-point-storage-at-first-use).
- **Zero-weight blend guard.** I ported upstream nxnative's source-side guard (seedds, `0662f9d8`): a pixel shader takes a NaN colour as 0 where its blend weight is zero. It changes the shader chain to `e00d4dfc770d`, so a new pack rebuilds its shader libraries. [Reference entry](../reference/shaders.md#a-nan-colour-with-a-zero-blend-weight).
- **Diagnostics.** `DM_NVN_DRAW_LAST` bisects the first draw that writes a wrong value, and the `DM_CTL` command `capture <path>` takes an `nvn_replay` capture of a live scene. `nvn_replay` gained the `DMRP_ZERO`, `DMRP_LIST`, `DMRP_DUMP` and `DMRP_DUMP_END` switches.

## Splatoon 3 12.0.0 online

Nextendo's signed 12.0.0 adapter needed three corrections before the game would connect:

- [its added code in the text segment's page padding](../reference/services.md#a-signed-adapter-adds-code-in-the-text-segments-page-padding), which the adapter step refused;
- [its embedded root certificate](../reference/rewriter.md#embedded-text-in-the-text-segment), which the native rewriter took for code and corrupted (`2321-4992`);
- [the provider's own public host name](../reference/services.md#a-signed-adapter-names-a-provider-host-by-its-own-public-name), which routing refused.

The calendar recipe now accepts 12.0.0 as well as 11.3.0.

## Online setup without Studio

A packed Mac game can now link or renew its Nextendo account itself. Reopen it holding Option and choose **Sign in with Nextendo** under **Online play** in its settings window. It uses the same Keychain item as Studio. When no firmware was ever chosen, Studio also takes the most recently imported firmware for a new port, instead of the built-in fallback resources.

## What I checked

- On my M5 Max I tested Splatoon 3 12.0.0 with Nextendo online. The plaza, the lobby and its practice area rendered correctly. The game stayed connected for the whole session, passed the NAT check and waited in the matchmaking queue. My replay of the probe-generation frames went from 1,790,418 NaN texels to none.
- The new GPU test `t_stale_float` passes, and fails as it should with the fix turned off. The new `blend_zero` rewrite test passes, including its compile for macOS and iOS.
- Tests that passed:
  - all 236 Python tool tests in the CI list;
  - the host suite, including 967 route checks, 297 TLS checks and 159 HID checks;
  - 29 gfx tests run;
  - all 113 gfx tests compiled;
  - 210 iPhone host sources compiled;
  - Studio's 109 Swift tests;
  - the launcher typecheck for both Apple SDKs.

## Limits

The server never assigned me a match in 12.0.0 or 11.3.0, so I have not completed a Splatoon 3 online match. I have not established whether the cause is the server's matchmaking, too few players in that mode, or something on the Mac. LAN/LDN, iPhone rendering, DLC gameplay and long sessions remain unqualified for this game. Rebuild a port to get these fixes; updating Studio does not update an exported app.
