# NX Port Studio 1.6.0 — Release Candidate 3

**Superseded by [RC4](1.6.0-rc.4.md).** RC4 retains this shader correction and adds native LAN/LDN setup fixes.

RC3 withdraws the unsafe BAHS shader-pair filter included in RC1 and RC2. Use this candidate instead of those releases.

## Correction

Upstream review of [nxnative #845](https://github.com/seedds/nxnative/pull/845) identified a real consumer of the pairs: passthrough geometry draws can use the original vertex and fragment stages. Those stages still need their pair for vertex output padding and pipeline prebuild. Removing it could make Metal reject the pipeline with “Fragment input not written”. The proposed optimization has been withdrawn; RC3 restores upstream pairing for geometry and tessellation programs.

The regression fixture now follows a synthetic passthrough program from BAHS pair discovery into the production pair-table loader and vertex-padding function. It also preserves the pair when an intermediate stage cannot be extracted. The shader split input fingerprint includes the changed reader, so future exports invalidate a cached split made with the old filter. Existing exported game apps are not rewritten by updating Studio; rebuild an affected port with RC3.

## Validation and limits

All 28 related pairing, padding and geometry tests pass (four optional native-harness checks skipped). The packaged Mac app passes signature and private-artifact checks. RC3 changes shader discovery, not the translation chain; the reference remains Xcode 27.2 / Metal 32023.922 and chain `a7dbbce711c3`.

The full host, graphics and synthetic iOS build validation of [RC2](1.6.0-rc.2.md) remains the preceding baseline. No new physical game session is claimed for this correction. Automatic LAN/LDN and experimental Nextendo functionality remain as documented in RC2. The Mac app uses a local ad-hoc signature and is not Developer ID notarized. No game, firmware, console key, account credential or signing identity is included.
